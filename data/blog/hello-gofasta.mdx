# Hello, Gofasta!

We've set up enough Go backends to know the first week by heart. Pick a router. Wire up logging. Choose a database client, then a migration tool that gets along with it. Write the same CRUD layers you wrote last time. Argue about where the handlers live. Copy a Dockerfile from the previous project and hope nothing rotted. None of that is your product. It's a toll, and most teams pay it in full on every new project.

Gofasta exists because we got tired of paying it.

## Two pieces, both MIT

**The CLI** lives at [`github.com/gofastadev/cli`](https://github.com/gofastadev/cli):

```bash
go install github.com/gofastadev/cli/cmd/gofasta@latest
```

It scaffolds projects, generates full CRUD layers from one command, runs migrations, regenerates dependency injection, and can tell you when your tree has drifted. It never imports the library at runtime. It only writes files.

**The library** lives at [`github.com/gofastadev/gofasta`](https://github.com/gofastadev/gofasta): thirty-odd packages under `pkg/*`, each one a thing backends keep needing. Config loading, JWT auth with RBAC, caching, structured errors, HTTP middleware, mailer, notifications, WebSockets, scheduled jobs, task queues, observability, feature flags, file storage, sessions, i18n, encryption, push. Each package is importable on its own; there's no umbrella that pulls everything in. The few cross-package dependencies are functional, not structural — `pkg/health` pings the database and the cache because that's literally what a health probe is for.

## The code is yours

Run `gofasta new myapp` and you get roughly 80 files of plain, idiomatic Go. The server is a stdlib `http.Server` with a [chi](https://github.com/go-chi/chi) router behind it. The commands you run (`serve`, `migrate`, `seed`) are ordinary Cobra subcommands. Models are GORM structs. Dependency injection resolves at compile time with [Google Wire](https://github.com/google/wire), so there's no reflection and no container magic to debug at 2am. You can read the whole project top to bottom in an afternoon.

Which is also the honest answer to "is this a framework?" No. There's no application object you register handlers into, no lifecycle that owns your code, no runtime that has to exist for your code to make sense. `go build`, `go test`, `golangci-lint`, Delve, your IDE — all of it behaves exactly as it does on any other Go project, because nothing is custom.

And it isn't lock-in. The scaffold imports `pkg/*` packages as opt-out defaults, the same way any Go service imports `chi` or `gorm.io/gorm`. Prefer a different JWT library? Delete the `pkg/auth` import and `go get` your alternative. Nothing else in the project has to change.

## A day with it

`gofasta new myapp` gives you the complete project: HTTP server, database layer, migration tooling, JWT auth with [Casbin](https://casbin.org) RBAC, `slog` logging, Swagger generation, Docker setup, and CI workflows ready to copy into `.github/workflows/`. Postgres is the default; `--driver` also takes `mysql`, `sqlite`, `sqlserver`, or `clickhouse`. Add `--graphql` and gqlgen comes wired up alongside REST. Pick `--layout layered` or `--layout feature` depending on how you like to organize code — and if you change your mind six months in, `gofasta refactor` converts an existing project between the two.

`gofasta g scaffold Article title:string body:text` gives you a model, migration, repository, service, DTOs, controller, route registration, a Wire provider, and tests for each layer. One resource, one command. The output is the code a careful Go engineer would have written by hand, and once it's generated the CLI doesn't watch it, sync it, or reconcile it. It's yours.

`gofasta dev` brings the local stack up: Docker services, migrations applied, [Air](https://github.com/air-verse/air) hot reload, and a debug dashboard if you ask for it. One terminal, no orchestration scripts.

That's the pattern everywhere: the CLI runs, writes files, and gets out of the way. No daemon, no hidden state.

## Built for your agent too

Most backend tooling treats AI coding agents as an afterthought. We treat your agent as a first-class consumer of the CLI, with specific needs: structured output, stable identifiers, and current documentation.

So every command takes a global `--json` flag for machine-readable output. Errors carry a stable machine-readable code, a one-line message, a remediation hint, and in most cases a link into the docs. `gofasta inspect` describes any resource in your project as structured data instead of making an agent grep for it. And `gofasta ai <agent>` installs tuned configuration — permission allowlists, hooks, agent briefings — for Claude Code, Cursor, OpenAI Codex, Aider, or Windsurf, without cluttering projects that don't use that particular agent.

The documentation site publishes [`/llms.txt`](https://gofasta.dev/llms.txt) and [`/llms-full.txt`](https://gofasta.dev/llms-full.txt), so agents can reason about what gofasta does today instead of what their training data remembers.

The bar we hold ourselves to: an agent working in a gofasta project should be measurably faster and more accurate than one working in a hand-rolled Go backend. That's a design constraint on every feature, not a product layered on top.

## What's in the box on day one

* HTTP routing via [chi](https://github.com/go-chi/chi)
* PostgreSQL, MySQL, SQLite, SQL Server, or ClickHouse, picked with `--driver` at scaffold time
* Migrations via [`golang-migrate`](https://github.com/golang-migrate/migrate)
* JWT authentication plus Casbin RBAC
* Structured logging via `slog`
* Caching (in-memory or Redis) and file storage (local or S3-compatible)
* Mailer with SMTP, SendGrid, and Brevo drivers
* WebSocket hub for real-time channels
* Scheduled jobs (`pkg/scheduler`) and async tasks (`pkg/queue`, backed by [asynq](https://github.com/hibiken/asynq))
* Circuit breaker and retry with exponential backoff
* Prometheus metrics and OpenTelemetry tracing
* Feature flags via the [OpenFeature](https://openfeature.dev) Go SDK
* Swagger/OpenAPI generation from code comments
* Docker setup plus `gofasta deploy` for VPS-over-SSH deployment, with health checks and automatic rollback
* A debug dashboard, build-tag-gated so it costs nothing in production

Pick what you use; delete what you don't.
