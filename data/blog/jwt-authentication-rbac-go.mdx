[Part one](/blog/build-production-rest-api-go) left us with a bookshelf API that works and that anyone on the internet can call. This post fixes that: hashed passwords, a login endpoint, JWT verification on every route, and Casbin deciding which role may do what.

## What the scaffold gives you, and what it doesn't

Gofasta wires the building blocks into the DI container. `app/di/container.go` holds a `*auth.JWTService` and an `*auth.RBACService`, and `config.yaml` has the settings:

```yaml
auth:
  jwt_secret: ""
  access_token_expiry: 15m
  refresh_token_expiry: 168h
  rbac_model: configs/rbac_model.conf
  rbac_policy: configs/rbac_policy.csv
```

The secret is empty on purpose. `gofasta new` wrote a random one to `.env` as `BOOKSHELF_AUTH_JWT_SECRET`, and the app refuses to boot if it resolves to empty or the placeholder. In production you set that variable on the host.

Before writing any code, I listed what is *not* there, because the generated README is upfront that scaffolded routes ship unprotected:

* No login, sign-up or refresh endpoint.
* No middleware on `/api/v1`. Every user and book route is public.
* `UserService.Create` stores its generated password as-is. Nothing hashes it.
* The `users` table has no role column, so there is nothing to put in a token's `role` claim.
* The Casbin policy is loaded at boot but never consulted.

So the services are there, and connecting them is our job. Five steps.

## Step 1: hash passwords

```bash
go get golang.org/x/crypto/bcrypt
```

In `app/services/user.service.go`, hash the generated password before it reaches the repository:

```go
pw, err := s.pwGen.Generate(16)
if err != nil { /* existing handling */ }

hash, err := bcrypt.GenerateFromPassword([]byte(pw), bcrypt.DefaultCost)
if err != nil {
	return nil, fmt.Errorf("UserService.Create: hash password: %w", err)
}

user := &models.User{
	// ...other fields unchanged
	Password: string(hash),
}
```

bcrypt is slow on purpose and salts each hash. It also silently ignores input past 72 bytes, so cap password length in your validators. How a new user learns or sets their password is a separate feature, usually an emailed set-password link.

## Step 2: give users a role

Add a migration after the books migration from part one, `db/migrations/000007_add_role_to_users.up.sql`:

```sql
ALTER TABLE "users" ADD COLUMN "role" character varying NOT NULL DEFAULT 'user';
```

The `.down.sql` drops the column. Then add the field to `app/models/user.model.go`:

```go
Role string `gorm:"not null;default:user"`
```

`gofasta migrate up` applies it. The default `user` matches the role name in the shipped Casbin policy.

## Step 3: login and refresh endpoints

`app/rest/controllers/auth.controller.go`:

```go
package controllers

import (
	"net/http"

	"github.com/gofastadev/gofasta/pkg/auth"
	apperrors "github.com/gofastadev/gofasta/pkg/errors"
	"github.com/gofastadev/gofasta/pkg/httputil"
	"golang.org/x/crypto/bcrypt"
	"gorm.io/gorm"

	"bookshelf/app/models"
)

type loginRequest struct {
	Email    string `json:"email" validate:"required,email"`
	Password string `json:"password" validate:"required,max=72"`
}

type refreshRequest struct {
	RefreshToken string `json:"refresh_token" validate:"required"`
}

type AuthController struct {
	db  *gorm.DB
	jwt *auth.JWTService
}

func NewAuthController(db *gorm.DB, jwt *auth.JWTService) *AuthController {
	return &AuthController{db: db, jwt: jwt}
}

func (c *AuthController) Login(w http.ResponseWriter, r *http.Request) error {
	in, err := httputil.BindJSON[loginRequest](r)
	if err != nil {
		return err
	}
	var user models.User
	err = c.db.WithContext(r.Context()).Where("email = ?", in.Email).First(&user).Error
	if err != nil || bcrypt.CompareHashAndPassword([]byte(user.Password), []byte(in.Password)) != nil {
		return apperrors.NewUnauthorized("invalid credentials", nil)
	}
	return c.issue(w, &user)
}

func (c *AuthController) Refresh(w http.ResponseWriter, r *http.Request) error {
	in, err := httputil.BindJSON[refreshRequest](r)
	if err != nil {
		return err
	}
	claims, err := c.jwt.ValidateToken(in.RefreshToken)
	if err != nil || claims.Role != "" {
		return apperrors.NewUnauthorized("invalid refresh token", nil)
	}
	var user models.User
	if err := c.db.WithContext(r.Context()).First(&user, "id = ?", claims.SubjectID()).Error; err != nil || !user.IsActive {
		return apperrors.NewUnauthorized("invalid refresh token", nil)
	}
	return c.issue(w, &user)
}

func (c *AuthController) issue(w http.ResponseWriter, user *models.User) error {
	access, err := c.jwt.GenerateToken(user.ID.String(), user.Role)
	if err != nil {
		return apperrors.NewInternal("could not issue token", err)
	}
	refresh, err := c.jwt.GenerateRefreshToken(user.ID.String())
	if err != nil {
		return apperrors.NewInternal("could not issue token", err)
	}
	return httputil.OK(w, map[string]string{"access_token": access, "refresh_token": refresh})
}
```

Two things in `Refresh` are there because of how `pkg/auth` behaves, and they cost me an afternoon:

* `JWTService.RefreshToken(str)` validates the token and mints a new access token with the old token's role. Refresh tokens carry no role, so the new access token has `role: ""`. Every Casbin check then fails. I reload the user and take the role from the database instead.
* Access and refresh tokens are signed the same way, with no type claim. The library will accept an unexpired access token as a refresh token, which would let one stolen access token be renewed forever. Rejecting tokens that carry a role is a workaround until the library adds a proper token type.

Reloading the user has a bonus: deactivating an account (`is_active = false`) stops its refreshes, which gives you revocation within one access-token lifetime.

The query lives in the controller for brevity. Once the auth code grows, move it into a `FindByEmail` method on the user repository.

## Step 4: protect the routes

`cmd/serve.go` already builds the health controller by hand, so I do the same for the auth pieces instead of touching Wire:

```go
apiRouter := routes.InitAPIRoutes(&routes.RouteConfig{
	UserController: container.UserController,
	AuthController: controllers.NewAuthController(container.DB, container.JWTService),
	JWT:            container.JWTService,
	RBAC:           container.RBACService,
	// ...existing fields
})
```

Add the three fields to `RouteConfig` in `app/rest/routes/index.routes.go`, then split the API into public and protected groups:

```go
api := chi.NewRouter()
api.With(middleware.RateLimit(config.RateLimitConfig{
	Enabled: true, Rate: "5-M", Store: "memory",
})).Post("/auth/login", httputil.Handle(cfg.AuthController.Login))
api.Post("/auth/refresh", httputil.Handle(cfg.AuthController.Refresh))

api.Group(func(r chi.Router) {
	r.Use(auth.JWTAuth(cfg.JWT), casbinGuard(cfg.RBAC))
	UserRoutes(r, cfg.UserController)
	BookRoutes(r, cfg.BookController)
	// gofasta:scaffold:route-registrations — keep this marker
})
r.Mount("/api/v1", api)
```

(I renamed the function's `config` parameter to `cfg` so it no longer shadows the `config` package.) Moving the scaffold marker inside the group means every resource you generate later lands behind auth by default. Login gets five attempts per minute per client, well under the global `rate_limit` of 100 per second.

`auth.RequirePermission(rbac, resource, action)` exists, but it takes a fixed resource and action per route. The shipped policy matches on URL path and HTTP method, so a ten-line guard fits it better:

```go
func casbinGuard(rbac *auth.RBACService) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			claims, err := auth.ClaimsFromContext(r.Context())
			if err != nil {
				_ = httputil.JSON(w, http.StatusUnauthorized, map[string]string{"error": "authentication required"})
				return
			}
			if ok, err := rbac.Enforce(claims.Role, r.URL.Path, r.Method); err != nil || !ok {
				_ = httputil.JSON(w, http.StatusForbidden, map[string]string{"error": "permission denied"})
				return
			}
			next.ServeHTTP(w, r)
		})
	}
}
```

chi's `Mount` leaves `r.URL.Path` as the full path, so it matches the policy's `/api/v1/*` patterns.

## Step 5: read the policy before trusting it

`configs/rbac_policy.csv` as generated:

```text
p, admin, /api/v1/*, (GET)|(POST)|(PUT)|(DELETE)
p, user, /api/v1/*, (GET)
p, user, /api/v1/users/*, (PUT)

g, admin, user
```

Two lines need attention. `user` may `GET /api/v1/*`, which includes listing every user's email and phone number. And `user` may `PUT /api/v1/users/*`, meaning *any* user's record. Path rules can't express ownership. For the bookshelf I removed the users PUT line and added an ownership check in the handler (`claims.SubjectID()` must equal the `{id}`). Policy changes are a CSV edit and a restart, and they show up in review as a diff.

## Trying it

Make yourself an admin. `htpasswd` produces a bcrypt hash that Go's bcrypt accepts:

```bash
HASH=$(htpasswd -bnBC 10 "" 'correct-horse' | tr -d ':\n')
docker compose exec db psql -U bookshelf bookshelf_dev -c \
  "UPDATE users SET password = '$HASH', role = 'admin' WHERE email = 'alice@example.com';"
```

Then:

```bash
curl -s localhost:8080/api/v1/books
# {"error":"authentication required"}

TOKEN=$(curl -s localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"alice@example.com","password":"correct-horse"}' | jq -r .access_token)

curl -s localhost:8080/api/v1/books -H "Authorization: Bearer $TOKEN"
# 200 with the paginated list
```

A garbage token gets `{"error":"invalid or expired token"}` from `JWTAuth`. A `user` trying to `POST` a book gets a 403 with `permission denied` from the guard.

## Things worth knowing

**Algorithms are pinned.** `ValidateToken` passes `jwt.WithValidMethods` for HS256, so `alg: none` and RS256-to-HS256 confusion are rejected.

**No clock leeway.** A token minted on a host whose clock runs ahead can fail as "not valid yet" elsewhere. Run NTP everywhere. The library doesn't add leeway.

**Browsers and cookies.** Keep tokens out of `localStorage`. `auth.JWTAuth(cfg.JWT, auth.WithCookieNames("access_token"))` also reads an HttpOnly cookie, and the login handler can set one instead of returning JSON. You then need CSRF protection on unsafe methods.

**Instant revocation.** A signed token stays valid until it expires. If 15 minutes is too long for your domain, `auth.WithCredentialResolver` lets clients hold an opaque handle that you look up, and delete, server-side.

**Timing.** The login above skips bcrypt when the email doesn't exist, so response time reveals whether an account exists. Comparing against a fixed dummy hash on that path closes the gap.

**The swap.** If none of this fits, `pkg/session` wraps gorilla/sessions for cookie-session auth, and an external identity provider fits behind the same `JWTAuth` middleware via `WithCredentialResolver`. Removing `pkg/auth` means editing the container and `providers/core.go`.
